# A_6(5,4) = 31

A self-contained proof. Every numbered claim below is either a two-line argument
or a command in `run-all.sh` / `run-all.ps1`.

---

## 1. Four names for one object

Let `C` be a code of length 5 over the alphabet `{0..5}` with minimum Hamming
distance 4. Two distinct words differ in at least 4 of 5 positions, so they
**agree in at most one position**. Conversely any set of length-5 words that
pairwise agree in at most one position has minimum distance at least 4. So

> `A_6(5,4)` = the largest set of words in `{0..5}^5` that pairwise agree in at
> most one coordinate.

That object is also called a packing array `PA(N;5,6,2)`, a partial transversal
design `TD(5,6)` with `N` blocks, and -- reading coordinates 0 and 1 as a cell
`(row, col)` of a 6x6 grid and coordinates 2,3,4 as the entries of three squares
in that cell -- a set of `N` filled cells carrying **three pairwise orthogonal
partial Latin squares of order 6**. The four counts are equal. The code notation
`A_6(5,4)`, the design notation `pa(5;6)` and the square notation are used
interchangeably below.

The search program is written in the square language: `S` squares means length
`K = S + 2` and distance `S + 1`. `S = 3` is the case of interest; `S = 2` gives
`A_6(4,3)`, which is known to be 34 and is used as a control.

---

## 2. Lower bound: A_6(5,4) >= 31

`certs/w31.txt` lists 31 words. `verify/verify.py` recomputes all
`C(31,2) = 465` pairwise Hamming distances from scratch and reports the minimum.
It is 4. Nothing else is needed for this direction.

    python3 verify/verify.py certs/w31.txt 6 4

The class profile it prints is `[6,5,5,5,5,5]` in every one of the five
coordinates. Keep that number in mind for section 3.

---

## 3. Ceiling: why N = 32 forces two full rows

Fix a coordinate `i` and group the words by their value there. Call these the
six **classes** of coordinate `i`.

**Lemma 1 (class size <= 6).** Two words in the same class already agree at
coordinate `i`, so they must differ in all four remaining coordinates. Project
the class onto the other four coordinates: it becomes a code of length 4 with
minimum distance 4, i.e. a set of pairwise-everywhere-different words. In
particular the first of those four coordinates takes a different value on each
word, so the class has at most 6 members.

**Lemma 2 (the number 31).** Suppose coordinate `i` has at most one class of
size exactly 6. Then

    |C| <= 6 + 5 * 5 = 31.

So **`|C| = 32` forces every coordinate to have at least two full classes.**

This is where 31 comes from. It is arithmetic, not search. Note also that 31 is
attainable only with class profile `(6,5,5,5,5,5)` -- exactly what the
certificate in section 2 has -- so the bound is tight at the profile level too.

The search below never has to discover the value 31. Its only job is to kill the
remaining possibility: a 32-word code, which by Lemma 2 must have two full
classes in the row coordinate.

---

## 4. The reduction

Assume `|C| = 32` and work in the square picture. By Lemma 2 the row coordinate
has two full classes, i.e. two grid rows with all 6 cells filled. Permuting rows
is a symmetry, so put them at rows 0 and 1. `H = 36 - 32 = 4` holes remain, all
in rows 2..5.

### 4.1 Row 0

Relabelling the symbols of each square independently is a symmetry. Row 0 is
full, so its six entries in square `s` are a permutation of `{0..5}`; relabel so
that `L_s(0,y) = y` for every square `s` and column `y`. Row 0 is now pinned.

### 4.2 Row 1: the seeds

Write `p_s(y) = L_s(1,y)`. Two constraints:

* `p_s(y) != y`, or the blocks at `(0,y)` and `(1,y)` would agree in column and
  in square `s`, i.e. twice;
* `p_s(y) != p_t(y)` for `s != t`, or those two blocks would agree in squares
  `s` and `t`.

So `{id, p_1, ..., p_S}` is an `(S+1) x 6` **Latin rectangle**. For `S = 3` there
are `393120` of them (equivalently: `265` derangements of `[6]`, `21280`
discordant pairs, `393120` pairwise-discordant triples).

The residual symmetry group after pinning row 0 is generated by

* **(a)** `p_s -> g p_s g^-1` for `g` in `S_6` -- permute columns and relabel
  symbols to match, keeping row 0 pinned;
* **(b)** any permutation of the `S` squares;
* **(c)** `p_s -> p_s^-1` -- swap grid rows 0 and 1, then relabel symbols of
  square `s` by `p_s^-1`. Rows 2..5 and the hole pattern are untouched.

`src/seeds.cpp` computes one representative per orbit: **103** for `S = 3`
(134 if (c) is dropped, 28 for `S = 2`). It does this by explicitly marking every
group image of every representative, so the list is complete and irredundant by
construction.

This is the only place where the argument could silently fail: a missing orbit
would make the search non-exhaustive and every `INFEASIBLE` verdict void.
So `verify/checkseeds.py` **re-derives it independently**, in Python, without
reading `seeds.cpp`: it builds all `393120` rectangles from scratch, expands the
103 listed seeds over the full group, and checks that the union is equal to the
full set -- `0` uncovered, `0` spurious. That check is step 3 of `run-all`.

### 4.3 Rows 2..5: the hole patterns

Each of rows 2..5 has a hole mask (a subset of the 6 columns), and the four
masks have total size `H = 4`. Rows 2..5 may be permuted freely -- that is a
symmetry of the object and it does not move rows 0,1, so it commutes with
everything in 4.2. Therefore only the **multiset** of masks matters, and the
search may enumerate multisets, i.e. masks sorted by `(popcount, mask)`.

The count is elementary. Split by the partition of `4` into at most four parts:

| mask sizes | count |
|---|---|
| `4` | `C(6,4) = 15` |
| `3 + 1` | `C(6,3) * C(6,1) = 120` |
| `2 + 2` | multiset of 2 from `C(6,2)=15` = `120` |
| `2 + 1 + 1` | `15 * ` multiset of 2 from 6 `= 15 * 21 = 315` |
| `1 + 1 + 1 + 1` | multiset of 4 from 6 = `C(9,4) = 126` |
| **total** | **696** |

`696` is exactly what `genPatterns()` emits. So this symmetry break is not merely
plausible or audited -- it is *counted*: the generator produces one
representative per orbit, no more and no fewer. (Without the break there are
`C(24,4) = 10626` patterns; `run-all --audit` re-runs the decisive case that way,
but the counting argument above already settles it, so the audit is optional.)

### 4.4 Size of the problem

    103 seeds  x  696 hole patterns  =  71688 subproblems

Each subproblem has rows 0 and 1 completely determined and 20 cells to fill in
rows 2..5, in three squares simultaneously.

## 5. The search

`src/searchA.cpp` fills the open cells in row-major order. At each cell it
assigns all `S` symbols together, so orthogonality is enforced immediately:
state is a row mask, a column mask and a symbol count per square, plus a 36-bit
used-pair mask per pair of squares.

Three prunes, all *necessary conditions*, so none of them can cut off a solution:

1. **Row Hall check.** For the remaining cells of the current row, take each
   square's candidate set `63 & ~rowmask & ~colmask` and test Hall's condition on
   every subset. Note this deliberately ignores the orthogonality constraint, so
   the candidate sets are supersets of the true domains and the test is
   conservative.
2. **Column capacity.** A column with `k` cells still to fill below row `r` needs
   at least `k` unused symbols in every square.
3. **Symbol capacity.** For each square, sum over symbols of
   `min(rows still available, columns still available)`; if that is below the
   number of cells still to fill, prune.

The traversal is deterministic and has no randomness, no restarts and no time
heuristics, so the node count is reproducible to the digit on any machine.

## 6. What the run establishes

| | |
|---|---|
| `searchA 3 32 seeds3.txt` | **INFEASIBLE (exhaustive)**, `1427441869` nodes |
| conclusion | no 32-word code exists, so `A_6(5,4) <= 31` |
| `verify.py certs/w31.txt` | a 31-word code exists, so `A_6(5,4) >= 31` |
| **therefore** | **`A_6(5,4) = 31`** |

Monotonicity does the rest: no 32 means no 33 or more, since deleting words from
a larger code would give a 32-word one.

## 7. Validation

A program that prints `INFEASIBLE` for the wrong reason proves nothing, so the
same program is made to answer questions whose answers are already known.

| check | expected | why it is a real test |
|---|---|---|
| `searchA 2 34` | FEASIBLE | `A_6(4,3) = 34` is in the literature; a search that over-prunes would miss it |
| `searchA 2 35` | INFEASIBLE | the same known value from the other side; a search that under-prunes or mis-encodes would find a phantom |
| `searchA 3 30` | FEASIBLE | positive control at the parameters that matter; rules out a search that refutes everything |
| `checkseeds.py` | 0 uncovered | second implementation of the only lossy step |
| `verify.py` | min distance 4 | the certificate is checked from first principles, not by the program that produced it |

The two-sided control on `A_6(4,3) = 34` is the important one: it pins the search
between a known SAT instance and a known UNSAT instance at adjacent values of
`N`, in the same code path, with only `S` changed.

## 8. What is not claimed

* No formal-methods certificate. This is a trusted C++ program cross-validated
  against known values, not a DRAT proof or a proof assistant development.
  Reproducing the node count on independent hardware, and re-deriving the seed
  list in a second language, are the mitigations offered.
* Nothing here is claimed about `A_6(6,5)`, `A_6(7,6)` or `z(43;2)`. This
  repository proves one number.
